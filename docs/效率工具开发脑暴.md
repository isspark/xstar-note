# XStar 笔记 · 效率工具开发脑暴

> 本文专门记录 XStar 笔记核心知识库功能之外的效率工具想法，方便后续挑选功能、组合需求和规划开发排期。
> 文中功能均为候选方案，不代表已经实现或已经确定进入下一版本。

---

## 1. 效率工具产品方向

在 Git 知识库、Markdown 笔记和 TODO 之外，XStar 笔记可以逐步扩展为个人效率工作台：

```text
知识管理 + 任务管理 + 时间管理 + 快速收集 + 安全信息管理 + 开发者工具箱
```

建议遵循两个原则：

- 番茄钟、提醒、习惯追踪等工具可以和 TODO 联动。
- 密码本、JSON 工具、代码片段等工具保持相对独立，不强行塞入笔记流程。

推荐最终形成的工作台结构：

```text
XStar 工作台
├── 知识库：Git 仓库、Markdown、搜索、Mermaid / draw.io
├── 任务：TODO、日历、提醒、周期任务
├── 时间：番茄时钟、专注记录、时间块
├── 收集：Inbox、快速便签、剪贴板、网页收藏
├── 安全：账号密码本、密码生成器、加密资料
└── 工具：JSON、Base64、URL、时间戳、UUID、Hash、正则、代码片段
```

- **P0**：适合近期做 MVP，能快速验证效率工具方向。

- **P2**：适合产品方向稳定后继续扩展。
- **P3**：涉及较大安全、同步或架构成本，暂不建议提前投入。

## 3. 时间管理工具

### 3.1 番茄时钟

不要只实现一个简单倒计时，建议将它设计成可关联任务的专注工具。

基础能力：

- 默认 25 分钟专注。
- 默认 5 分钟短休息。
- 默认 15 或 30 分钟长休息。
- 自定义专注、短休息和长休息时长。
- 开始、暂停、继续、跳过和重置。
- 后台运行。
- 通知栏显示剩余时间和当前阶段。
- 锁屏通知。
- 专注完成后自动进入休息。
- 今日完成番茄数统计。

建议的界面：

```text
专注中
补充同步冲突说明

18:42
第 2 / 4 个番茄

[暂停] [结束专注]
```

和 TODO 联动：

```text
正在处理：补充同步冲突说明
当前番茄：第 2 个
已专注：48 分钟
```

第一版建议只实现：

1. 独立番茄钟。
2. 可选关联一个 TODO。
3. 后台计时和通知。
4. 完成后保存一次专注记录。

建议数据表：

```text
focus_sessions
- id
- todoId?
- title
- startedAt
- endedAt?
- plannedMinutes
- actualMinutes
- status
- interruptionCount
```

### 3.2 专注模式

番茄时钟之上的增强模式：

- 只显示当前任务和倒计时。
- 隐藏无关入口。
- 防止误触退出。
- 可选屏蔽通知。
- 播放白噪音或环境音。
- 结束后显示简单总结。

暂不建议第一版加入复杂环境音资源，先把计时可靠性和通知体验做好。

### 3.3 时间块计划

用时间段安排任务：

```text
09:00 - 10:30  编码
10:30 - 10:45  休息
14:00 - 15:00  文档整理
20:00 - 20:30  学习
```

后续可支持：

- 将 TODO 放入时间块。
- 查看当天时间安排。
- 对比计划时间和实际专注时间。
- 识别经常超时的任务。

该功能复杂度高于番茄钟，建议后置。

### 3.4 习惯追踪

适合记录重复行为：

- 每日阅读。
- 每日运动。
- 每日写日记。
- 每周整理仓库。
- 每天背单词。
- 每晚复盘。

候选能力：

- 打卡。
- 连续天数。
- 月历热力图。
- 目标频率。
- 漏打卡提醒。
- 习惯完成率。

习惯与 TODO 的语义不同：

- TODO 关注一次性行动。
- 习惯关注重复发生。

建议使用独立数据表：

```text
habits
- id
- name
- note
- frequencyRule
- color
- enabled

habit_records
- habitId
- date
- completedAt
```

### 3.5 重要日期提醒

可记录和提醒：

- 证书到期。
- 域名续费。
- 软件订阅续费。
- 生日。
- 保修到期。
- 项目节点。
- 合同到期。
- 定期备份。

需要区分两类数据：

- TODO：需要完成的行动。
- 日期提醒：某个时间点需要关注。

第一版可以复用现有任务通知机制，但建议在界面和数据语义上与 TODO 分开。

## 4. 账号密码本

### 4.1 密码本功能范围

每条账号记录可以包含：

- 网站或服务名称。
- 登录地址。
- 用户名。
- 密码。
- 邮箱。
- 手机号。
- 备注。
- 标签。
- 收藏状态。
- 创建时间。
- 修改时间。
- 密码强度。
- 密码更新时间。

示例：

```text
GitHub
用户名：example@email.com
密码：••••••••••
```

候选操作：

- 点击显示或隐藏密码。
- 一键复制用户名。
- 一键复制密码。
- 复制后自动清除剪贴板。
- 搜索账号名称、用户名和网址。
- 按标签筛选。
- 收藏常用账号。
- 查看密码强度。
- 查看密码修改时间。
- 查看修改历史。

### 4.2 密码生成器

支持自定义：

- 密码长度。
- 大写字母。
- 小写字母。
- 数字。
- 特殊字符。
- 排除容易混淆的字符。
- 生成易读密码。

示例设置：

```text
长度：20
大写：是
小写：是
数字：是
特殊字符：是
```

密码生成器可以独立于密码本先实现，开发成本低，也能提前验证安全工具的使用需求。

### 4.3 必须提前确定的安全边界

密码本不能按照普通 Room 数据或普通 Markdown 文件处理。

建议：

- 使用 Android Keystore 保存主密钥。
- 敏感字段使用 AES-GCM 加密。
- 数据库只保存密文，不保存明文密码。
- 进入密码本前要求设备锁或生物识别验证。
- App 切到后台时自动隐藏密码。
- 默认禁止密码页面截图，或提供明确的用户设置。
- 复制密码后延迟清除剪贴板。
- 不将密码写入日志。
- 不把密码本内容加入普通全文搜索索引。
- 导出默认不包含明文密码。
- 如需导出，必须使用强制加密格式。
- 不通过普通 Android 备份导出明文数据。

建议独立出安全模块：

```text
PasswordVault
├── VaultKeyManager
├── EncryptedVaultRepository
├── BiometricUnlockController
└── ClipboardClearController
```

建议数据表：

```text
vault_entries
- id
- titleCipher
- usernameCipher
- passwordCipher
- urlCipher?
- noteCipher?
- tagsCipher?
- favorite
- createdAt
- updatedAt
```

### 4.4 密码本同步策略

建议明确分阶段处理：

1. 第一版只做本地加密存储。
2. 第二版做加密备份和手动导入导出。
3. 最后再评估跨设备同步。

不建议第一版直接把密码本密文放入普通 Git 同步流程。即使字段已经加密，也需要先解决密钥派生、设备迁移、版本冲突、恢复和密钥丢失等问题。

### 4.5 敏感信息扫描

可以扫描 Git 仓库中的潜在敏感信息：

- Access Token。
- API Key。
- 私钥文件。
- `.env` 文件。
- 密码字段。
- 数据库连接串。
- 云服务密钥。
- 证书文件。

示例：

```text
发现潜在敏感信息
文件：config/example.env
行号：12
类型：疑似 API Key

[忽略] [移除] [加入 .gitignore]
```

扫描结果只在本地展示，不应上传到远程仓库。

## 5. 快速记录与信息收集

### 5.1 Inbox 收集箱

所有临时内容先进入统一收集箱：

```text
Inbox
├── 从浏览器分享的文本
├── 待处理链接
├── 截图
├── 快速记录
└── 尚未分类的 TODO
```

之后再整理为：

- Markdown 笔记。
- 本地 TODO。
- 今日笔记。
- 网页收藏。
- 账号密码记录。
- 已归档内容。

这样可以避免用户在记录当下就决定仓库、目录和分类。

### 5.2 快速便签

类似临时草稿：

- 打开即输入。
- 自动保存。
- 不要求标题。
- 后续转为 Markdown。
- 后续转为 TODO。
- 后续追加到今日笔记。
- 后续归档或删除。

第一版可以直接把快速便签作为 Inbox 的一种内容类型，避免同时维护两个相似入口。

### 5.3 剪贴板主动收集

提供用户主动触发的剪贴板工具：

- 读取当前剪贴板。
- 一键保存为笔记。
- 一键转为 TODO。
- 一键追加到今日笔记。
- 一键搜索相关文档。
- 立即清除剪贴板。

安全约束：

- 不要长期在后台读取剪贴板。
- 只有用户主动打开时才读取。
- 可能包含密码的内容不应自动索引。
- 提供明显的清除操作。

### 5.4 网页收藏与稍后阅读

支持从浏览器分享链接：

```text
标题：Android 官方文档
链接：https://developer.android.com
备注：需要研究 Compose adaptive
```

候选能力：

- 保存网页标题和链接。
- 手动添加备注。
- 标记已读或未读。
- 转成 Markdown。
- 添加 TODO。
- 标签分类。
- 关联项目仓库。

第一版只保存标题、链接和备注即可，不急于抓取网页正文。

## 6. 开发者效率工具箱

### 6.1 JSON / XML / 编码工具

建议提供一个独立的“开发工具箱”，每个工具单独页面：

- JSON 格式化。
- JSON 压缩。
- JSON Diff。
- XML 格式化。
- Base64 编码和解码。
- URL 编码和解码。
- 时间戳转换。
- UUID 生成。
- Hash 计算。
- JWT 解析。
- 正则表达式测试。
- Cron 表达式解释。

安全边界：

- 输入内容默认不保存历史。
- 涉及 Token 的工具提供清空按钮。
- JWT 只做本地结构解析，不表示已经验证身份。
- 不自动上传用户输入内容。

### 6.2 代码片段库

保存常用代码和配置：

- Shell 命令。
- Git 命令。
- SQL。
- Kotlin。
- JavaScript。
- 正则表达式。
- Docker 配置。
- CI 配置。
- Android 配置。

功能：

- 语法高亮。
- 标签。
- 复制代码。
- 关联仓库。
- 变量占位符。
- 代码片段搜索。
- 一键插入当前 Markdown。

示例：

```text
adb 清理并重装应用
./gradlew :app:assembleDebug
```

### 6.3 命令收藏与参数生成器

支持命令模板和参数：

```text
命令模板：
adb -s {device} shell am force-stop {package}

参数：
device = emulator-5554
package = com.xstar.notebook
```

生成结果：

```bash
adb -s emulator-5554 shell am force-stop com.xstar.notebook
```

候选能力：

- 参数说明。
- 参数默认值。
- 危险命令提醒。
- 复制。
- 分享。
- 标签。
- 最近使用记录。

对于 `rm -rf`、`git push --force` 等命令，应显示明显警告，并要求二次确认后复制或执行。

### 6.4 API 请求测试工具

轻量版可以支持：

- GET、POST、PUT、DELETE。
- Header 编辑。
- Query 参数。
- Body 编辑。
- JSON 格式化。
- 响应状态码。
- 响应耗时。
- 响应保存为笔记。
- 请求模板收藏。

该功能复杂度明显高于本地转换工具，建议后置。

提供系统级快捷入口：

- 打开 Inbox。
- 打开密码本。

- 打开默认仓库。

### 8.4 小组件增强

在现有 TODO 小组件基础上增加：

- 今日任务小组件。
- 快速新建 TODO。
- 快速新建笔记。
- 番茄钟小组件。
- 最近文档小组件。
- 仓库同步状态小组件。
- Inbox 小组件。
- 指定分类 TODO 小组件。

## 9. 推荐开发组合

### 组合 A：专注工作流

适合验证时间管理方向：

```text
番茄时钟
   ↓
关联 TODO
   ↓
保存专注记录
   ↓
今日工作台统计
   ↓
周回顾
```

首批范围：

- 番茄计时。
- 后台通知。
- 关联一个 TODO。
- 完成后保存专注记录。
- 工作台显示今日番茄数和专注时长。

### 组合 B：安全工具

适合独立规划安全产品线：

```text
本地加密存储
   ↓
生物识别解锁
   ↓
密码生成器
   ↓
安全复制与自动清除
   ↓
加密备份
   ↓
最后再考虑同步
```

首批范围：

- 密码生成器。
- 本地加密账号记录。
- 生物识别解锁。
- 密码显示和隐藏。
- 复制后自动清除剪贴板。
- 密码强度提示。

### 组合 C：开发者工具箱

适合低成本增加高频工具：

```text
JSON
├── 格式化
├── 压缩
└── Diff
编码
├── Base64
├── URL
└── 时间戳
开发辅助
├── UUID
├── Hash
├── JWT
└── 正则测试
```

首批范围：

- Base64 编解码。
- URL 编解码。
- 时间戳转换。
- UUID 生成。
- Hash 计算。

### 组合 D：快速收集工作流

适合提高 App 的日常打开频率：

```text

   ↓

   ↓

   ↓

```

首批范围：

- Inbox。
- 快速便签。
- 系统分享接收文本和链接。
- 转换为 Markdown 或 TODO。
- 今日笔记追加。

## 10. 推荐开发路线

### 第一阶段：低风险 MVP

建议从下面功能中挑选 2 到 3 个：

1. 番茄时钟。
2. 番茄时钟关联 TODO。
3. Inbox 基础收集。
4. JSON / Base64 / URL / 时间戳工具箱。
5. 代码片段库。

这一阶段的目标是验证用户是否愿意把 XStar 笔记当作日常效率入口。

### 第二阶段：增强日常使用

1. 重要日期提醒。
2. 习惯追踪。
3. 每日启动页。
4. 网页收藏与稍后阅读。
5. 命令收藏与参数生成器。
6. 系统分享和 App Shortcuts。
7. 番茄统计和周回顾。

1. 密码生成器。
2. 本地加密密码本。
3. 生物识别解锁。
4. 安全复制和剪贴板自动清除。

6. Git 仓库敏感信息扫描。

密码本建议作为独立专项规划，不要在没有安全设计的情况下直接与普通笔记共用存储和搜索逻辑。

### 第四阶段：复杂工具和自动化

1. 时间块计划。
2. 个人资料保险箱。
3. 证件和合同资料管理。
4. 设备及软件资产管理。
5. API 请求测试工具。
6. 自动化规则。
7. 加密跨设备同步。

## 12. 产品边界待决策

在正式开发前，建议优先确认：

1. 密码本第一版是否只允许本地存储。
2. 是否允许密码本内容导出，以及导出格式如何加密。
3. Inbox 是独立于 Git，还是默认落到某个仓库。
4. 番茄钟是否必须关联 TODO，还是允许完全独立使用。
5. 效率工具是否都出现在首页，还是统一收进工具箱。
6. 首页是知识库首页、效率首页，还是允许用户选择首页模式。
7. 是否优先适配平板、桌面窗口和外接键盘。
8. 剪贴板内容是否允许保存历史，以及默认保存多久。
9. 开发工具的输入是否默认不保存。
10. 是否允许敏感信息扫描自动修改文件或 `.gitignore`。
